## 「记一笔」标签管理入口失效（用户报告）+ 标签管理重做

**现象**：在「记一笔」里点「+ 添加标签」→「管理标签」，界面没有任何反应。

**根因**：不是层级/遮挡的样式问题，而是**跳了路由**。两个弹窗的「管理标签」都是 `onClose()` + `navigate('/categories')`，而「记一笔」是 **App 级常驻全屏覆盖层**（`App.tsx` 的 `showAddTransaction`，始终挂载），路由切走后覆盖层仍在最上层，把分类页整个挡住。而且 `/categories`（`Categories.tsx`）**没有任何标签管理代码**，`AppContext.updateTag` / `deleteTag` **全仓 0 调用方** —— 此前只能"搜索时顺带新建标签"。两个弹窗只被「记一笔」引用，所以该 bug **必现**。

**修复**：
- 新增 `components/TagManagerModal.tsx`，就地弹窗管理（portal 到 body、z-[100]），结构上不可能再被遮挡，也不会把用户从编辑现场带走。
- `TagSelectModal` / `SubCategoryManagerModal`：删 `useNavigate`，改必填回调 prop `onManageTags`（TS 必填 prop 校验保证了接线完整）。
- `AddTransaction`：记录来源弹窗，关闭管理器后回到原处；关闭时剔除被删掉的标签 id，避免表单留死 id。

**优化**：补齐新建/重命名/改色/删除（`updateTag`/`deleteTag` 首次被使用）；重名校验（忽略大小写与空格）；配色轮换 + 抽出共用 `utils/colorPalette.ts`（原先新建标签恒为 `#818cf8`，且调色板在两个组件里各抄一份）；列表按"被多少笔交易引用"倒序并显示次数（一次遍历建 Map，不 N×全表）；删除行内二次确认并提示影响面；选择弹窗补「全部标签」（原来只显示最近 6 个，其余只能靠搜索）；创建时同名直接选中；保存失败不再静默。

**验证**：`tsc` 84 → 84（零新增），`npm run build` 通过（10.55s），全仓 grep 确认两个弹窗已无 `navigate`、`/categories` 只剩 Settings 的正常入口。**未做**：真机/线上点击验证（本地无登录态），需部署后走一遍。

**约定（已记入 MEMORY.md）**：从「记一笔」这类常驻覆盖层内部触发的操作一律用弹窗，不要 `navigate()`。

## 删除标签留下悬空引用（用户报告）

**核实结论：属实**。交易 `tags` 存的是**标签 id 数组**，`AppContext.deleteTag` 只 `localTags.remove(id)` + `setTags(filter)`，**不清理交易引用** → 悬空 id（引用表已无、界面不显示、重建同名也接不回来）。

**同类缺陷共 4 处**：`deleteTag`(tags[]) / `deleteSubCategory`(subcategory_id) —— 已修；`deleteCategory`(category_id) / `deleteAccount`(account_id) —— **未修**（必填字段，需先定策略）。

**修法**：`local-operations.ts` 加 `localTransactions.removeTagFromAll` / `clearSubCategoryFromAll`（扫该用户交易 → 摘引用 → 复用 `update` 走 markDirty，返回改动过的交易 id）；`deleteTag`/`deleteSubCategory` 调它并同步更新内存 state + 补 `syncAfterWrite('transactions')`；`SubCategoryManagerModal` 补使用次数与删除二次确认（原先是点一下直接删、无提示，而删除现在会级联，破坏性变强）。

**数据体检（线上实测）**：4121 笔交易 / 598 笔带标签；tag、subcategory_id、category_id、account_id 四类悬空引用**全部为 0** → A2 那 3 笔修完后无残留，**不需要修数据**。顺便确认 `tags` 只被 `transactions.tags` 引用（transfers 无标签字段），级联一处即完整。

**验证**：tsc 84 → 84（零新增）、build 通过（8.16s）。**待做**：部署后线上真删一个标签，确认悬空引用仍为 0。

**未决问题（待用户回话）**：2026-07-06 「深圳游玩」150.00 那笔现在没有标签（备注仍在，信息没丢）—— 若想恢复标签，需重建同名标签再挂上。**我的判断：不重建** —— 该标签本来就是用户自己删掉的，重建等于否定他的操作；备注还在，信息没丢。

## 浏览器实测（Chrome CDP 直连 localhost:5173）

用户已登录的 Chrome + dev server 跑本地代码，真点了一遍：管理标签弹窗**命中测试 `elementFromPoint` 落在弹窗自身（covered=false）** —— 原 bug 确实修好；来源弹窗会先关、关掉管理器会回到原弹窗；31 个标签的使用次数全部算出且按引用数倒序；新建自动取未占用的 `#4ecdc4`（原来恒为 `#818cf8`）；重名校验拦下「瑞幸」；删除二次确认正常；**级联清理实测生效**（注入测试标签 → UI 删标签 → 该交易 tags 由 2 回到 1）；子分类管理入口同样正常。

**验证数据的技巧（可复用）**：要测"删除会级联清理引用"但又**不能污染线上**时——用 CDP 在页面里直接写 IndexedDB（`indexedDB.open("MyBillsDB")`），把测试标签 id 注入一笔**真实交易的本地记录**，并**保持 `_sync_status='synced'` 不变**（这样同步引擎不会推它）；跑完再用 SQL 复查线上那条交易没变 ✓ 净效果为零。Chrome 的 `indexedDB.databases()` 可探库名，`cdp.mjs eval` 会等待 Promise 返回值。
